# Cinema Buddy: Movie Booking Website and Machine Learning Project

**Technology:** React, Tailwind CSS, Node.js, Express, MongoDB, Python, PyMongo, scikit-learn  
**Date:** 28 October 2026

## 1. Introduction

Cinema Buddy is a basic movie-booking website. Users can browse movies, choose a showtime and seats, make a booking, and view or cancel their bookings. A built-in chat assistant guides users through the booking flow and explains available movie choices.

The code is organized into two main folders: `frontend` contains the website, and `backend` contains the API and ML service. The Node API uses a simple Model-View-Controller structure:

```text
backend/
  server.js                 Express entry point
  config/database.js        MongoDB connection
  models/                   Movie and booking database operations
  controllers/              API request handling
  routes/                   API URL definitions
  ml-service/               Python ML model and Flask service
frontend/
  src/                      React application and styles
```

## 2. Project objectives

1. Create an easy-to-use, responsive movie-booking website.
2. Implement film browsing, genre filters, seat selection, booking history, and cancellation.
3. Let users complete the main booking tasks through a chat assistant.
4. Store movie and booking records in MongoDB.
5. Use PyMongo in Python to store machine-learning metrics and predictions.
6. Train and evaluate ML models and report Accuracy, R², MAE, precision, recall, and F1.

## 3. Dataset description

The project creates a reproducible dataset of 1,200 synthetic showtime observations. The dataset is generated by `backend/ml-service/model.py` at startup and saved as `backend/ml-service/data/movie_demand.csv`.

| Column | Description |
|---|---|
| `movie_id` | One of six sample movie identifiers |
| `day_of_week` | Day number from 0 (Monday) through 6 (Sunday) |
| `show_hour` | Showtime hour: 12, 15, 18, or 21 |
| `bookings` | Generated booking count; regression target |
| `high_demand` | 1 if bookings are at least 75; otherwise 0 |

Generated booking counts use sample movie popularity, weekend and evening effects, and seeded random noise. These are demo data, not real cinema booking records.

## 4. MongoDB and PyMongo implementation

The Node API connects to MongoDB database `cinema_buddy`. It creates a movie catalogue and saves bookings with the movie, date, showtime, seat count, total price, confirmation code, and booking status.

The Python ML service connects to the same database with `pymongo.MongoClient`. It saves evaluation results in `ml_metrics` and prediction records in `demand_predictions`.

Main Node API routes:

| Route | Purpose |
|---|---|
| `GET /api/movies` | Read the film catalogue |
| `GET /api/bookings` | Read recent bookings |
| `POST /api/bookings` | Create a booking |
| `DELETE /api/bookings/:id` | Cancel a booking |
| `GET /api/demand` | Request an ML demand estimate |

## 5. Data preprocessing

The data-generation script produces the features and target columns. The `movie_id` category is one-hot encoded. `day_of_week` and `show_hour` remain numeric. The dataset is split into 80% training and 20% test data with a fixed random state.

## 6. Model implementation

Two Random Forest models are used:

- `RandomForestRegressor` predicts the number of bookings for a movie and showtime.
- `RandomForestClassifier` predicts whether the showtime will have high demand (75 or more bookings).

Both models use 180 trees and a fixed random state for repeatable results. The demand prediction is shown in the website’s booking panel. It does not restrict a user from booking.

## 7. Evaluation results

The service calculates each metric on the held-out test data. The reproducible training script was run with scikit-learn 1.5.2; the results below are measured values from its 240-row test set.

| Metric | Model | Where to find the result |
|---|---|---|
| Accuracy | High-demand classifier | 0.8000 |
| R² score | Booking-count regressor | 0.6868 |
| MAE | Booking-count regressor | 8.3175 bookings |
| Precision | High-demand classifier | 0.6087 |
| Recall | High-demand classifier | 0.8235 |
| F1 score | High-demand classifier | 0.7000 |

The dataset has 1,200 rows (960 train and 240 test). The fixed random seed makes this run reproducible with the specified dependency versions. The dataset is synthetic, so its scores demonstrate the pipeline rather than real-world accuracy.

## 8. Website and chat assistant

The React and Tailwind frontend provides the movie catalogue, genre filters, booking form, booking history, and chat panel. A theme menu supports Day, Night, and Auto (follow device preference) modes.

## 9. How to run

Start MongoDB, then use three terminals. From `backend`, run `npm install` and `npm run dev` to start the Node API. From `backend/ml-service`, create and activate a Python environment, install `requirements.txt`, and start `app.py`. From `frontend`, run `npm install` and `npm run dev` to launch the UI.

## 10. Conclusion

Cinema Buddy demonstrates a simple, working movie-booking flow using React, Node.js, and MongoDB, with chat-based controls and a Python/PyMongo machine-learning service. Its synthetic dataset makes it easy to demonstrate the workflow without needing a real cinema dataset.
